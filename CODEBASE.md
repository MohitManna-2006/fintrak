## 1. Project Overview

Fintrak is a full-stack personal finance application with collaborative shared expense tracking. It combines personal finance management (transactions, budgets, goals) with a shared rooms system (split expenses, debt simplification, settle-up), all augmented by an AI copilot powered by Anthropic's Claude.

**Core capabilities:**
- Track personal income and expenses by category
- Set and monitor monthly budgets per category
- Create savings goals with contribution tracking and progress visualization
- AI copilot with persistent conversation history for financial advice
- Smart daily nudges generated by AI (budget alerts, goal pace warnings, spending spikes, month-end trajectory)
- Shared expense rooms — invite friends, split bills equally or with custom weights, track who owes what, mark settlements
- Room-scoped AI copilot with awareness of the room's expense history

```bash
GOOGLE_CLIENT_SECRET="GOCSPX-xxxx"

# Anthropic
ANTHROPIC_API_KEY="sk-ant-xxxx"
```

### ⚠️ DATABASE_URL Notes

- **App runtime** uses port `6543` (pgBouncer transaction pooler)
- **`prisma db push` / migrations** must use port `5432` (session mode or direct)
- The direct host `db.PROJECT_ID.supabase.com:5432` may be **blocked** from local machines — use the session-mode pooler instead:

```bash
DATABASE_URL="postgresql://postgres.PROJECT_ID:PASSWORD@aws-1-us-east-1.pooler.supabase.com:5432/postgres" npx prisma db push
```

## 7. Authentication & Access Control

### Route Groups

| Group | Path prefix | Layout behavior |
|---|---|---|
| `(auth)` | `/login` | No auth check, public |
| `(dashboard)` | `/dashboard`, `/transactions`, `/budgets`, `/goals`, `/copilot` | Requires auth **AND** `user.onboarded === true` — redirects to `/onboarding` if not |
| `(rooms)` | `/rooms`, `/rooms/[id]` | Requires auth only — **onboarding is NOT required** so room guests can access immediately |
| root | `/join/[token]`, `/onboarding` | Individual page-level auth checks |

### Invite Link Flow (full trace)

```
1. Room member clicks "Invite" button
   → POST /api/rooms/[id]/invite
   → Creates RoomInvite (token = cuid, expiresAt = now + 7 days)
   → Returns { token, expiresAt }
   → UI constructs: https://fintrak-lime.vercel.app/join/{token}
   → Copies to clipboard

2. Recipient opens the link: /join/{token}
   └── Not signed in?
       → redirect("/login?callbackUrl=/join/{token}")
       → Login page reads callbackUrl, passes to signIn("google", { redirectTo: callbackUrl })
       → Google OAuth → returns to /join/{token}
   └── Already signed in → continues directly

3. /join/[token] server component:
   - Looks up RoomInvite by token
   - If not found → "Invalid Invite" error page
   - If expiresAt < now → "Invite Expired" error page
   - If user already a member → skips INSERT
   - Creates RoomMember { userId, roomId, role: "member" }
   - redirect("/rooms/{roomId}")

4. /rooms/[id] renders via (rooms) layout
   - Checks auth only (no onboarding check)
   - New users with onboarded=false can access rooms ✓
```

### `proxy.ts` Auth Guard

Handles one additional case: if an unauthenticated user navigates to `/dashboard/*`, they're redirected to `/login`. This is a redundant safety check — the layout does the same thing — but it prevents any server component work from happening for unauth'd requests.

## 8. API Routes

### Personal Finance

#### `GET /api/transactions`
Returns transactions for the authenticated user. Supports query params:
- `?month=3&year=2026` — filter by month/year (defaults to current month)

#### `POST /api/transactions`
Create a new transaction.
```json
{
  "amount": 45.00,
  "type": "expense",
  "category": "Food & Dining",
  "description": "Dinner",
  "date": "2026-03-18"
}
```

#### `PUT /api/transactions/[id]`
Update a transaction (ownership checked).

#### `DELETE /api/transactions/[id]`
Delete a transaction (ownership checked).

---

#### `GET /api/budgets`
Returns all budgets for the user. Optional `?month=&year=` filter.

#### `POST /api/budgets`
Create or update a budget (upsert by userId + category + month + year).
```json
{ "category": "Food & Dining", "limit": 400, "month": 3, "year": 2026 }
```

#### `DELETE /api/budgets`
Delete a budget entry by `?id=`.

---

#### `GET /api/goals`
Returns all goals ordered by deadline ascending.

#### `POST /api/goals`
Create a goal.
```json
{ "name": "Emergency Fund", "targetAmount": 5000, "deadline": "2026-12-31", "color": "#00c896" }
```

#### `PUT /api/goals/[id]`
Edit goal fields (name, targetAmount, deadline, color).

#### `PATCH /api/goals/[id]`
Add a contribution. Increments `currentAmount` (capped at `targetAmount`).
```json
{ "contribution": 200 }
```

#### `DELETE /api/goals`
Delete a goal (ownership checked via `?id=`).

---

#### `POST /api/copilot`
Streaming AI chat for personal finance. Sends full conversation history + user's financial context (transactions, budgets, goals, income) as system prompt.

Response: `text/plain` stream (chunks of assistant text).

Request body:
```json
{ "messages": [{ "role": "user", "content": "How am I doing this month?" }] }
```

#### `GET /api/copilot/history`
Returns last 50 chat messages for the user.

---

#### `GET /api/notifications`
Returns `{ notifications: [...], unreadCount: number }`. Last 20 notifications.

#### `PATCH /api/notifications`
Marks all user notifications as read.

---

#### `POST /api/onboarding`
Completes onboarding setup.
```json
{
  "monthlyIncome": 5000,
  "currency": "USD",
  "financialGoal": "Build emergency fund",
  "budgets": [
    { "category": "Food & Dining", "limit": 400 }
  ]
}
```
Sets `user.onboarded = true`. Creates budgets for current month. Creates an income transaction if monthlyIncome > 0.

---

### Rooms API

#### `GET /api/rooms`
Returns all rooms the user is a member of. Each room includes computed `myBalance`.

#### `POST /api/rooms`
Create a new room. Creator is auto-added as admin.
```json
{ "name": "Barcelona Trip", "budgetCap": 2000 }
```

---

#### `GET /api/rooms/[id]`
Full room detail. Returns:
- `members` with computed per-member `balance`
- `transactions` (last 50, ordered by date desc)
- `settlements` (ordered by createdAt desc)
- `invites`
- `debts` (simplified debt lines from `simplifyDebts()`)
- `myBalance`
- `totalExpenses`

Requires user to be a room member.

#### `PATCH /api/rooms/[id]`
Update room name or budgetCap. Creator only.

#### `DELETE /api/rooms/[id]`
Delete room (and all cascading records). Creator only.

---

#### `POST /api/rooms/[id]/invite`
Creates a new invite token (7-day expiry). Any room member can call this.

Returns: `{ token: string, expiresAt: string }`

---

#### `DELETE /api/rooms/[id]/members?userId=xxx`
Leave a room (`userId` = current user) or remove a member (admin only). Cannot remove the room creator.

---

#### `GET /api/rooms/[id]/transactions`
Room's full transaction list with splits and user info.

#### `POST /api/rooms/[id]/transactions`
Add a room expense with split data.
```json
{
  "description": "Dinner",
  "amount": 120.00,
  "category": "Food & Drink",
  "date": "2026-03-18",
  "paidByUserId": "user_abc",
  "splitType": "equal",
  "splits": [
    { "userId": "user_abc", "amount": 40.00 },
    { "userId": "user_def", "amount": 40.00 },
    { "userId": "user_ghi", "amount": 40.00 }
  ]
}
```

For `splitType: "equal"`, splits are computed server-side. For `splitType: "weighted"`, the client sends custom amounts (must sum to `amount`).

#### `DELETE /api/rooms/[id]/transactions/[txId]`
Delete a room transaction. Allowed: the person who added it, or any room admin.

---

#### `GET /api/rooms/[id]/settle`
Returns `{ debts: DebtLine[], settlements: Settlement[] }`. Debts are the simplified settlement suggestions.

#### `POST /api/rooms/[id]/settle`
Record a settlement (debt repayment).
```json
{ "fromUserId": "user_abc", "toUserId": "user_def", "amount": 40.00, "note": "Venmo" }
```

---

#### `POST /api/rooms/[id]/copilot`
Streaming AI chat scoped to room data. System prompt includes room members, recent transactions, settlements, and total expenses.

Request: `{ "messages": [...] }`
Response: streaming `text/plain`

---

#### `GET /api/cron/nudges`
Protected by `Authorization: Bearer {CRON_SECRET}` header (Vercel sets this automatically). Processes all `onboarded: true` users sequentially and generates AI nudge notifications.

## 9. Pages & UI Routes

### `/login` — Login Page
- Google OAuth only
- Reads `?callbackUrl=` from search params (validated to be a relative `/` path)
- If already signed in → redirects to `callbackUrl` (or `/dashboard`)
- Form action passes `callbackUrl` to `signIn("google", { redirectTo })`

### `/onboarding` — Onboarding Flow
- Multi-step form: currency → monthly income → financial goal → budget setup
- If `user.onboarded === true` → redirects to `/dashboard`
- On completion → POST `/api/onboarding` → redirects to `/dashboard`

### `/dashboard` — Main Dashboard
- Summary cards: net balance, total income, total expenses, savings rate
- Charts: spending by category (pie), monthly trend (line/bar)
- Recent transactions list
- Budget progress bars (current month)
- Notification bell with dropdown (wired to `/api/notifications`)

### `/transactions` — Transaction History
- Full transaction list with category filter, month/year filter
- Add transaction modal
- Edit/delete per row
- Income vs expense color coding

### `/budgets` — Budget Manager
- Budget cards per category showing limit and current spend
- Progress bars with color thresholds (green → amber → red)
- Create/edit/delete budget modals
- Month navigation

### `/goals` — Savings Goals
- 2-column grid (1-column mobile) of goal cards
- Color accent bar, glowing status dot
- Status badges: `COMPLETE` / `OVERDUE` / `URGENT` / `IN PROGRESS`
- 3px progress bar with glowing endpoint
- Add/Edit modal with name, target, deadline, 6-color picker
- Contribute modal showing remaining amount
- Delete confirmation modal
- Skeleton loading, empty state
- Mobile: slides up from bottom, full-width buttons

### `/copilot` — Personal AI Copilot
- Streaming chat interface
- Conversation history persisted to `ChatMessage` table
- System prompt includes user's full financial context

### `/rooms` — Shared Rooms List
- Room cards showing name, member avatars, total expenses, personal balance
- Balance indicators: green (owed to you), red (you owe), grey (settled)
- Create room modal (name + optional budget cap)
- Mobile: cards stack vertically, full-width create button

### `/rooms/[id]` — Room Detail
Three tabs:

**Expenses tab**
- Transaction feed (description, category badge, payer, timeago, amount, your share)
- Add Expense modal: description, amount, category, date, payer selector, equal/custom split
- Custom split: per-member amount inputs, live validation that splits sum to total
- Delete button (transaction creator or admin)

**Settle Up tab**
- "Who Owes What" — simplified debt list from `simplifyDebts()` algorithm
- Color-coded: your debts in red, amounts owed to you in green
- Settle button → confirm modal with optional note → POST `/api/rooms/[id]/settle`
- Settlement history below debts

**Copilot tab**
- Streaming chat aware of room context
- Blinking cursor on streaming messages
- Empty state prompt

### `/join/[token]` — Invite Join Page
Server component. Auto-joins user to room and redirects to `/rooms/[id]`.
- Not authenticated → redirects to `/login?callbackUrl=/join/[token]`
- Invalid token → error page with link to `/rooms`
- Expired token → error page
- Already a member → skips duplicate insert

### `src/lib/auth.ts`

```typescript
export const { handlers, auth, signIn, signOut } = NextAuth({
  adapter: PrismaAdapter(db),
```

### `src/lib/rooms.ts`
Debt computation utilities.

**`computeUserBalance(userId, transactions, settlements)`**
```
balance = 0
For each transaction:
  if paidBy === userId: balance += amount  (you're owed back)
  if splits includes userId: balance -= split.amount  (you owe your share)
For each settlement:
  if toUserId === userId: balance += amount  (you received money)
  if fromUserId === userId: balance -= amount  (you paid someone)
Return rounded to 2 decimal places
```

**`computeAllBalances(members, transactions, settlements)`**
Returns a `Map<userId, balance>` for all room members.

**`simplifyDebts(balances, nameMap)`**
Greedy debt simplification algorithm:
1. Split members into `creditors` (balance > 0.005) and `debtors` (balance < -0.005)
2. Sort both arrays descending by amount
3. Loop: match largest creditor with largest debtor
4. Debt = `min(creditor.amount, debtor.amount)`
5. Reduce both by that amount, remove any that reach near-zero
6. Produces the minimum number of payments needed to settle all debts

Returns `DebtLine[]`: `{ from, fromName, to, toName, amount }`

## 12. Shared Rooms Feature

### Data model relationships
```
Room
  ├── RoomMember[] (userId, role: admin|member)
  ├── Transaction[] (paidByUserId, splitType, splits: TransactionSplit[])
  ├── RoomInvite[] (token, expiresAt)
  └── Settlement[] (fromUserId, toUserId, amount, note)
```

### Split Types
- **Equal**: Server computes each member's share. Rounding remainder goes to the first member.
- **Weighted (Custom)**: Client sends custom per-member amounts. API validates all split userIds are room members. Client validates sum equals total amount.

### Debt Simplification Algorithm
Located in `src/lib/rooms.ts → simplifyDebts()`.

Example: Alice paid $90, Bob paid $30. Equal 3-way split → each owes $40.
- Alice's balance: +90 (paid) - 40 (her share) = **+50** (owed $50)
- Bob's balance: +30 (paid) - 40 (share) = **-10** (owes $10)
- Charlie's balance: 0 - 40 (share) = **-40** (owes $40)

After simplification:
- Charlie pays Alice $40
- Bob pays Alice $10

This runs fresh on every `GET /api/rooms/[id]` and `GET /api/rooms/[id]/settle` call — it's always computed from live transaction + settlement data, never cached.

## 15. Middleware & Proxy

**File:** `src/proxy.ts` (not `middleware.ts` — Vercel uses this naming convention)

```typescript
export default function proxy(req: NextRequest) {
  // Inject current pathname as header (used by layouts to build callbackUrl)
  const headers = new Headers(req.headers);
  headers.set("x-pathname", nextUrl.pathname);

  // Public routes pass through
  if (isPublicRoute) return NextResponse.next({ request: { headers } });

  // Dashboard requires auth
  if (isDashboardRoute && !isAuthenticated) {
    return NextResponse.redirect(new URL("/login", nextUrl));
  }

  return NextResponse.next({ request: { headers } });
}
```

**Auth cookie detection:** Checks 4 cookie name variations to support both Auth.js v5 and older next-auth:
- `__Secure-authjs.session-token`
- `authjs.session-token`
- `__Secure-next-auth.session-token`
- `next-auth.session-token`

**`x-pathname` header:** Set on every request. Read by `(rooms)/layout.tsx` to reconstruct a `?callbackUrl=` for the login redirect, so bookmarked room URLs survive a sign-out/sign-in cycle.

**Matcher:**
```
/((?!_next/static|_next/image|favicon\.ico|.*\..*).*)
```
Excludes static assets and files with extensions. Runs on all page routes.

## 17. Known Issues & Debugging Notes

### Fixed Issues (documented for reference)

**`P2022: column not available` on Vercel after schema changes**
- Cause: `prisma db push` was run against the dev DB but not production.
- Fix: Run `db push` with the production `DATABASE_URL` using port 5432 (session pooler).

**Login page ignoring `?callbackUrl=`**
- Cause: The form action hardcoded `redirectTo: "/dashboard"`.
- Fix: Login page now accepts `searchParams` prop, reads and validates `callbackUrl`, and passes it to `signIn()`.

**`(rooms)/layout.tsx` losing the URL on redirect**
- Cause: Layout redirected to `/login` without `callbackUrl`.
- Fix: `proxy.ts` injects `x-pathname` header; layout reads it via `headers()` and builds `?callbackUrl=`.

**Build error: conflicting `middleware.ts` + `proxy.ts`**
- Cause: Created `src/middleware.ts` when `src/proxy.ts` already existed (Vercel uses `proxy.ts` as the middleware convention).
- Fix: Deleted `middleware.ts`, merged logic into `proxy.ts`.

**`myplit` typo in rooms balance computation**
- Cause: Typo in `src/app/api/rooms/route.ts` — `if (myplit)` instead of `if (mySplit)`.
- Fix: Replaced inline `computeUserBalance` function with import from `src/lib/rooms.ts`.

**`prisma db push` failing with "datasource.url property required"**
- Cause: Running `npm run db:push` uses the prisma.config.ts which reads `DATABASE_URL` from env, but the local `.env.local` uses the pooler URL (port 6543) which Prisma can't use for schema push.
- Fix: Pass `DATABASE_URL` inline as an env var prefixed to the command.

**Bell badges not visible**
- Cause: Original badges were 12px with 7px font, hidden inside button bounds.
- Fix: Enlarged to 18–20px, repositioned outside corner, added red glow `box-shadow`.

**Notification bell click doing nothing on dashboard**
- Cause: The bell in `dashboard-client.tsx` was a `<div>` with `cursor: pointer` but no click handler or state.
- Fix: Replaced with `<button>` + full notification state, `getBoundingClientRect` for dropdown positioning.

### Supabase Outage Behavior
When Supabase goes down, the app shows "Server error / There is a problem with the server configuration" — this is NextAuth failing to query/write sessions. Nothing to fix in code; wait for Supabase to resolve. Monitor: **status.supabase.com**.

### RLS (Row Level Security)
All tables show **UNRESTRICTED** in the Supabase dashboard. RLS is disabled. The app enforces data access at the API route level (ownership checks, membership checks). This is intentional for simplicity but should be revisited before any public/multi-tenant launch.
